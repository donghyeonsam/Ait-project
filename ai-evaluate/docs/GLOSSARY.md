# 용어 사전

코드와 문서에 나오는 낯선 단어들을 쉬운 말로 정리했다.

---

## 데이터 관련

**바이트 (byte)**
파일 내용물 그 자체. 컴퓨터의 모든 파일은 결국 숫자 덩어리인데, 그걸 담는 단위다.
택배로 치면 파일은 "주소 붙은 상자", 바이트는 "상자 안 내용물"이다.
→ **바이트로 보내나 파일로 보내나 데이터는 완전히 같다. 분석 결과도 같다.**

**코덱 (codec)**
소리나 영상을 압축하는 방식. mp3, opus 같은 것들.
사진으로 치면 "jpg로 저장했다"에서 jpg에 해당한다.

**컨테이너 (container)**
압축한 데이터를 담는 상자. webm, mp4 같은 것들.
"zip 폴더에 담았다"에서 zip 폴더에 해당한다.
→ 브라우저 녹음은 보통 **webm 상자에 opus로 압축한 소리**를 담아준다.

**샘플레이트 (sample rate)**
1초에 소리를 몇 번 기록하는가. 48000이면 초당 48000번.
촘촘할수록 원본에 가깝다. 낮추면 목소리의 미세한 떨림을 못 잡는다.

**손실 압축 / 무손실 압축**
- 손실: 사람이 못 느끼는 부분을 버려서 용량을 줄임 (mp3, opus). 원본으로 못 되돌림
- 무손실: 하나도 안 버리고 줄임 (flac). 원본으로 완벽히 되돌림

## 서버 관련

**동기 / 비동기**
- 동기: 라면 올려놓고 냄비 앞에서 기다리기. 끝날 때까지 딴 일 못 함
- 비동기: 라면 올려놓고 딴 일 하다가 나중에 확인하기

**@Async (스프링)**
"이 일은 오래 걸리니까 다른 직원한테 맡기고 나는 딴 일 할게"라는 표시.

**큐 (queue) / 대기열**
줄 서기. 은행 번호표 시스템이라고 보면 된다.
일이 밀리면 순서대로 쌓아두고 하나씩 처리한다.

**Celery**
파이썬용 번호표 시스템. 일을 큐에 넣어두고 별도 프로그램(worker)이 꺼내서 처리한다.
→ **우리 기본 구성에서는 안 쓴다.** BE가 이미 @Async로 기다리고 있어서 필요 없다.

**폴링 (polling)**
"다 됐어요?" 하고 주기적으로 계속 물어보는 것.
번호표 방식을 쓰면 이걸 해야 한다. 우리는 안 써도 된다.

**세마포어 (semaphore)**
동시 입장 인원 제한 장치. 주차장 자리 개수라고 생각하면 된다.
자리가 2개면 3번째 차는 누가 나갈 때까지 밖에서 기다린다.
→ 음성 분석이 한꺼번에 몰려 CPU가 터지는 걸 막는다.

**타임아웃 (timeout)**
"이 시간 넘으면 그냥 포기해"라는 제한 시간.
- connect timeout: 연결되기까지 기다리는 시간
- read timeout: 답장을 기다리는 시간 ← **이게 짧으면 분석 끝나기 전에 끊긴다**

**TTL (유통기한)**
Redis에 저장한 데이터가 자동으로 사라지는 시간.
안 걸어두면 데이터가 계속 쌓여 메모리가 꽉 찬다.

**임시 파일**
잠깐 저장했다 지우는 파일. 우리는 받은 바이트를 분석 도구에 넘기려고 잠깐 저장한다.
(도구들이 "파일 위치를 알려줘"라고 요구해서)

## 분석 관련

**MediaPipe**
구글이 만든 얼굴 인식 도구. 사진에서 얼굴 위 478개 점의 위치를 찾아준다.
브라우저에서도 돌아가서, 우리는 이걸 프론트에서 쓴다.

**랜드마크 (landmark)**
얼굴 위의 점들. 눈꼬리, 입꼬리, 코끝 같은 위치.

**blendshape**
"이 표정 근육이 얼마나 움직였나"를 나타내는 52개 숫자.
예: 왼쪽 눈 감김 0.8, 눈썹 올림 0.2, 입꼬리 올림 0.5...
MediaPipe가 랜드마크에서 자동 계산해준다.

**EAR (Eye Aspect Ratio)**
눈이 얼마나 떠 있는지 나타내는 비율. 눈을 감으면 값이 작아진다.
→ 이 값이 갑자기 작아지는 순간을 세면 "깜빡임 횟수"가 된다.

**MAR (Mouth Aspect Ratio)**
입이 얼마나 벌어졌는지. 말을 많이 하면 변동이 커진다.

**librosa**
파이썬 음성 분석 도구. 음량, 발화 속도, 음색 같은 걸 계산한다.

**Praat / parselmouth**
음성학 연구에서 표준으로 쓰는 프로그램(Praat)과 그 파이썬 연결 도구(parselmouth).
목소리 떨림 같은 정밀한 지표를 계산한다. **브라우저에는 대체품이 없다.**

**성대 펄스 / PointProcess**
성대가 열렸다 닫히는 순간들의 시각 목록.
목소리 떨림(jitter)은 "이 순간들 사이 간격이 얼마나 들쭉날쭉한가"를 재는 거라
이 목록이 반드시 필요하다.

**jitter (지터)**
성대 진동 주기의 미세한 흔들림. 목소리가 거칠고 불안정할수록 커진다.

**shimmer (시머)**
소리 크기의 미세한 흔들림. 음량이 떨릴수록 커진다.

**HNR**
맑은 소리 대 잡음의 비율. 높을수록 또렷하고 안정적인 목소리.

**F0 (기본 주파수)**
목소리의 높낮이. 남성은 보통 85~180Hz, 여성은 165~255Hz.

## 머신러닝 관련

**MLP (다층 퍼셉트론)**
가장 기본적인 형태의 인공 신경망. 숫자 여러 개를 넣으면 숫자 몇 개가 나온다.
우리 모델은 아주 작아서(수십 KB) 계산이 거의 공짜다.

**피처 (feature) / 특징 벡터**
모델에 넣을 숫자 묶음. 예: 표정은 116개 숫자, 음성은 38개 숫자.

**라벨 (label)**
정답. "이 답변의 긴장도는 0.7이다" 같은 것. 사람이 매기거나 다른 모델이 만들어준다.

**집계 (aggregation)**
여러 개를 하나로 요약하기. 프레임 450개의 결과를 평균 내서 숫자 하나로 만드는 것.
→ 답변 길이가 제각각이어도 모델 입력 크기를 똑같이 맞출 수 있다.

**학습 / 추론**
- 학습(training): 데이터를 보여주며 모델을 만드는 과정. 우리는 개발자 노트북에서 한다
- 추론(inference): 만들어진 모델로 실제 판단하는 것. 서버에서 한다

**distillation (지식 증류)**
무겁고 똑똑한 모델(선생)의 답을 흉내 내도록 작은 모델(학생)을 가르치는 방법.
학습이 끝나면 선생은 버리고 학생만 서버에 올린다.
→ 우리 음성 모델이 이 방식이다. 덕분에 서버에 GPU가 필요 없다.

**과적합 (overfitting)**
모델이 학습 데이터를 '이해'한 게 아니라 '외워버린' 상태.
시험 문제를 이해 못 하고 답만 외운 것과 같아서, 처음 보는 문제에는 완전히 틀린다.
→ 데이터가 적을 때 잘 생긴다. 우리가 가장 조심해야 할 문제다.

**train / validation 분할**
가진 데이터의 80%로 학습하고, 20%는 숨겨뒀다가 채점에 쓴다.
숨긴 데이터로 채점해야 "외운 게 아니라 진짜 아는지"를 확인할 수 있다.

**data leakage (데이터 유출)**
숨겨둔 채점용 데이터의 정보가 학습에 새어 들어간 상태. 점수가 실제보다 높게 나온다.
예: 같은 사람이 찍은 영상이 학습용과 채점용에 나뉘어 들어가면, 모델이 긴장도가 아니라
그 사람 얼굴을 외워서 맞힐 수 있다.

**training-serving skew**
학습할 때 쓴 데이터 처리 방식과 실제 서비스의 방식이 다른 상태.
채점 점수는 좋은데 실제 서비스만 이상한 상황이 되고, 원인 찾기가 매우 어렵다.
→ 우리가 `core/` 폴더를 만들어 학습·추론이 같은 코드를 쓰게 한 이유다.
