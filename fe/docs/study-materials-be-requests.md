# 자료실 BE 협의 사항

갱신일: 2026-08-07. 스터디 그룹 자료실(`/study/groups/:id/materials`)이 FE만으로는 해결할 수 없는 항목을 정리한다.

## 반영 완료 (2026-08-07 BE 파일 전송 구현 기준)

- **자료실 전용 조회 API** — `GET /api/study-groups/{groupId}/files?type=image|other&page=&size=`가 생겨 FE가 그룹톡 히스토리 스캔 대신 이 API로 탭별 페이지네이션한다. `totalElements`로 종류별 전체 개수, `fileSize`로 용량, `fileType`으로 종류 판별까지 해결됐다.
- **채팅 파일 정식 스키마** — `chatType: FILE` + `files[]` 전송으로 전환했고, 업로드도 채팅 전용 `POST /api/study-groups/files/upload(s)`를 쓴다.

## 남은 협의 항목 (우선순위 순)

### 1. 과거 파일 토큰 자료 처리

새 스키마 도입 전에 `[file:...]` 토큰 텍스트로 공유된 파일은 `study_group_files` 테이블에 없어 모아보기 API에 잡히지 않는다. FE는 임시로 전용 API 페이지를 다 읽은 뒤 그룹톡 히스토리를 이어서 훑어 과거 자료를 보여주고 있다(`fe/src/api/study-materials.ts`의 legacy 단계). 과거 토큰 메시지를 `study_group_files`로 마이그레이션해주면 이 스캔 로직을 제거할 수 있다. 과거 데이터를 버려도 된다고 결정해도 무방하며, 그 경우에도 FE 코드만 정리하면 된다.

### 2. 파일명 검색 파라미터

`GET .../files`에 `keyword=` 검색이 없어 FE 검색이 "지금까지 불러온 자료" 안에서만 동작한다. 서버 검색이 생기면 전체 범위 검색으로 전환한다.

### 3. 이미지 썸네일

그리드 썸네일이 원본 이미지를 그대로 받는다. FE에서 뷰포트 진입 시에만 받도록 완화했지만, 원본이 수 MB면 근본 해결이 아니다. 업로드 시 썸네일 생성 또는 리사이즈 파라미터(`?w=300` 등)를 협의한다.

### 4. 업로드 제한 스펙 공유

`POST /api/study-groups/files/upload(s)`의 파일 크기·확장자·개수 제한 값을 공유받으면 업로드 전에 "파일 하나당 ○MB까지 올릴 수 있어요"처럼 구체적으로 검증·안내할 수 있다. 현재는 서버가 거부해야 실패를 알 수 있다.

### 5. (선택) 자료 삭제 정책

자료가 그룹톡 메시지에서 파생되므로 자료 삭제 = 메시지(첨부) 삭제다. 자료실에서 본인 자료(또는 그룹장 권한) 삭제를 제공할지, 채팅 쪽 삭제 API와 어떻게 맞물릴지 정책 협의가 필요하다.
