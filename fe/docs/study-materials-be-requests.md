# 자료실 BE 협의 사항

작성일: 2026-08-07. 스터디 그룹 자료실(`/study/groups/:id/materials`)이 FE만으로는 해결할 수 없는 항목을 정리한다. 우선순위 순.

## 현재 FE 구조와 한계

전용 자료실 API가 없어 그룹톡 히스토리 조회(`GET /api/study-groups/{groupId}/chats`)를 여러 페이지 훑으며 파일 토큰 메시지만 걸러 자료 목록을 만든다(`fe/src/api/study-materials.ts`).

- 자료 12개를 채울 때까지 채팅을 최대 10페이지 연속 조회한다. 채팅이 많고 첨부가 드문 그룹일수록 요청 낭비가 커진다.
- 전체 자료 개수를 알 수 없어 탭 카운트가 "지금까지 불러온 개수"에 그친다.
- 파일명 검색·올린 사람 필터가 이미 불러온 자료에만 적용된다.
- 채팅 스키마에 파일 크기가 없어 목록에 용량을 표시하지 못한다.

## 1. 자료실 전용 조회 API (효과 가장 큼)

그룹의 첨부만 서버에서 걸러 내려주는 API를 요청한다.

```
GET /api/study-groups/{groupId}/materials
  ?type=image|file      # 선택: 종류 필터
  &keyword=...          # 선택: 파일명 검색
  &uploaderId=...       # 선택: 올린 사람 필터
  &lastId=...&size=...  # 커서 페이지네이션
```

응답에 필요한 필드:

- `chatId`(또는 자료 id), `storedFilename`, `originalFilename`, `fileSize`
- `uploaderId`, `uploaderNickname`, `createdAt`
- 종류별 전체 개수(`imageCount`, `fileCount`) — 탭 카운트용, 별도 요약 API여도 무방

이 API가 생기면 FE의 히스토리 스캔 로직을 제거하고 검색·필터를 서버 기준(전체 범위)으로 전환한다.

## 2. 이미지 썸네일

그리드 썸네일이 원본 이미지를 그대로 받는다. FE에서 뷰포트 진입 시에만 받도록 완화했지만, 원본이 수 MB면 근본 해결이 아니다. 업로드 시 썸네일 생성 또는 리사이즈 파라미터(`?w=300` 등)를 지원하는 방안을 협의한다.

## 3. 업로드 제한 스펙 공유

`POST /api/files/upload`의 파일 크기·확장자·개수 제한 값을 공유받아야 한다. 현재는 서버가 거부해야 실패를 알 수 있어 "올리지 못했어요"로만 안내한다. 제한 값을 알면 업로드 전에 "파일 하나당 ○MB까지 올릴 수 있어요"처럼 구체적으로 검증·안내할 수 있다.

## 4. (선택) 자료 삭제 정책

자료가 그룹톡 메시지에서 파생되므로 자료 삭제 = 메시지 삭제다. 자료실에서 본인 자료(또는 그룹장 권한) 삭제를 제공할지, 제공한다면 채팅 쪽 삭제 API와 어떻게 맞물릴지 정책 협의가 필요하다.
